# 📖 Glosario de Términos - Sistema de Ahorro Colaborativo

## 🏦 Términos de Negocio

### **Acción (Stock)**
Tipo de participación financiera que un miembro puede tener en el fondo. Cada acción tiene un valor específico y puede generar rendimientos.

### **Ahorro Colaborativo**
Sistema financiero donde múltiples miembros contribuyen regularmente a un fondo común para obtener beneficios colectivos.

### **Asiento Contable (Ledger Entry)**
Registro individual en el sistema de contabilidad de doble entrada que documenta una transacción financiera.

### **Contribución Obligatoria (Mandatory Contribution)**
Pago mensual requerido que cada miembro debe realizar según el tipo de acción que posee.

### **Desembolso (Disbursement)**
Pago o distribución de fondos a los miembros del sistema.

### **Dividendo**
Distribución de ganancias entre los miembros según su participación en el fondo.

### **Efectivo Disponible**
Monto de dinero líquido disponible para operaciones y desembolsos.

### **Fondo Familiar**
El capital total del sistema de ahorro colaborativo.

### **Libro Contable**
Sistema de contabilidad de doble entrada que registra todas las transacciones financieras.

### **Miembro (Member)**
Persona que participa en el sistema de ahorro colaborativo.

### **Operación Financiera**
Transacción que afecta el estado financiero del sistema (pagos, préstamos, revalorizaciones, etc.).

### **Préstamo (Loan)**
Cantidad de dinero que se presta a un miembro con condiciones específicas de pago.

### **Reunión (Meeting)**
Sesión donde se registran y procesan las operaciones financieras del sistema.

### **Revalorización de Activos (Asset Revaluation)**
Proceso de actualización del valor de las acciones según el rendimiento del fondo.

### **Suscripción de Acciones (Stock Subscription)**
Relación entre un miembro y un tipo de acción específico.

## 🛠️ Términos Técnicos

### **ADR (Architecture Decision Record)**
Documento que registra una decisión arquitectónica importante, incluyendo el contexto, opciones consideradas y justificación.

### **API REST**
Interfaz de programación de aplicaciones que utiliza el protocolo HTTP para comunicación entre servicios.

### **Backend**
Parte del sistema que maneja la lógica de negocio, base de datos y procesamiento de datos.

### **Base de Datos**
Sistema de almacenamiento persistente de datos del sistema.

### **Controlador (Controller)**
Componente que maneja las peticiones HTTP y coordina la respuesta del sistema.

### **DTO (Data Transfer Object)**
Objeto que transporta datos entre capas del sistema sin exponer la estructura interna.

### **Entidad (Entity)**
Representación de un objeto de negocio en la base de datos.

### **Frontend**
Parte del sistema que maneja la interfaz de usuario y la interacción con el usuario.

### **Inyección de Dependencias**
Patrón de diseño donde las dependencias se proporcionan a un objeto en lugar de crearlas internamente.

### **Módulo**
Unidad organizacional del código que agrupa funcionalidades relacionadas.

### **MVP (Minimum Viable Product)**
Producto mínimo viable que incluye las funcionalidades esenciales para validar el concepto.

### **NestJS**
Framework de Node.js para construir aplicaciones del lado del servidor.

### **ORM (Object-Relational Mapping)**
Técnica que mapea objetos de programación a tablas de base de datos.

### **Servicio (Service)**
Componente que contiene la lógica de negocio del sistema.

### **Swagger/OpenAPI**
Especificación para documentar APIs REST.

### **TypeORM**
ORM para TypeScript y JavaScript que simplifica el trabajo con bases de datos.

### **TypeScript**
Lenguaje de programación que extiende JavaScript con tipado estático.

## 🏗️ Términos Arquitectónicos

### **Arquitectura en Capas**
Patrón arquitectónico que organiza el código en capas con responsabilidades específicas.

### **CQRS (Command Query Responsibility Segregation)**
Patrón que separa las operaciones de lectura y escritura en diferentes modelos.

### **Domain-Driven Design (DDD)**
Enfoque de diseño de software que se centra en el dominio del negocio.

### **Event-Driven Architecture**
Arquitectura donde los componentes se comunican mediante eventos.

### **Microservicios**
Arquitectura donde la aplicación se divide en servicios pequeños e independientes.

### **Monolito**
Arquitectura donde toda la aplicación se ejecuta como una sola unidad.

### **Patrón Repository**
Patrón que abstrae el acceso a datos proporcionando una interfaz uniforme.

### **SOLID**
Principios de diseño de software: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.

## 📊 Términos de Calidad

### **Cobertura de Tests**
Porcentaje del código que está cubierto por tests automatizados.

### **Testing de Integración**
Tests que verifican la integración entre diferentes componentes del sistema.

### **Testing Unitario**
Tests que verifican el funcionamiento de unidades individuales de código.

### **Testing E2E (End-to-End)**
Tests que verifican el flujo completo de la aplicación desde la perspectiva del usuario.

### **Refactoring**
Proceso de reestructurar el código existente sin cambiar su comportamiento externo.

### **Code Review**
Proceso de revisión del código por parte de otros desarrolladores.

## 🔒 Términos de Seguridad

### **Autenticación**
Proceso de verificar la identidad de un usuario.

### **Autorización**
Proceso de determinar qué permisos tiene un usuario autenticado.

### **JWT (JSON Web Token)**
Estándar para crear tokens de acceso que permiten la comunicación segura entre partes.

### **CORS (Cross-Origin Resource Sharing)**
Mecanismo que permite recursos web en un dominio acceder a recursos en otro dominio.

### **Rate Limiting**
Técnica que limita el número de solicitudes que un usuario puede hacer en un período de tiempo.

## 🚀 Términos de DevOps

### **CI/CD (Continuous Integration/Continuous Deployment)**
Práctica de automatizar la integración y despliegue de código.

### **Containerización**
Técnica de empaquetar aplicaciones con sus dependencias en contenedores.

### **Docker**
Plataforma para desarrollar, enviar y ejecutar aplicaciones en contenedores.

### **Kubernetes**
Sistema de orquestación de contenedores para automatizar el despliegue y escalado de aplicaciones.

### **Pipeline**
Secuencia automatizada de pasos para construir, probar y desplegar software.

## 📈 Términos de Performance

### **Caché**
Almacenamiento temporal de datos frecuentemente accedidos para mejorar el rendimiento.

### **Escalabilidad**
Capacidad del sistema para manejar un aumento en la carga de trabajo.

### **Performance**
Medida de qué tan rápido y eficientemente funciona el sistema.

### **Optimización**
Proceso de mejorar el rendimiento del sistema.

## 🔄 Términos de Proceso

### **Agile**
Metodología de desarrollo de software que enfatiza la colaboración, flexibilidad y entrega incremental.

### **Sprint**
Período de tiempo fijo durante el cual se completa un conjunto de trabajo.

### **User Story**
Descripción de una funcionalidad desde la perspectiva del usuario final.

### **Backlog**
Lista de tareas o funcionalidades pendientes de implementar.
